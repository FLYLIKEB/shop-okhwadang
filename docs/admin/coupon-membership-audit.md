# 쿠폰·회원 등급 전수 점검

점검일: 2026-10-12 · 관련 이슈: #1290

## 범위와 기준

어드민 쿠폰·자동 발급 규칙, 고객 쿠폰함·체크아웃, 발급·사용·취소 복원, 회원 등급 저장·조회·재평가·구매 확정 연동을 확인했다.
실제 PG 결제·고객 발송·운영 데이터 소급 수정 없이 코드, 단위 테스트, HTTP 및 실제 MySQL 경합 테스트로 검증한다.

## 등급은 이미 존재한다

`membership_tiers`와 `users.tier`, `tier_accumulated_amount`, `tier_evaluated_at`이 실제 엔티티와 마이그레이션에 있다.
회원 등급 조회 API는 `/api/users/me/tier`, 관리자 설정 API는 `/api/admin/membership-tiers`다.
어드민 회원 목록에서 현재 등급과 누적액을 볼 수 있으며, 쿠폰 규칙의 등급 선택은 이 설정 API를 사용한다.

| 기본 등급 | 기본 최소 누적액 | 저장된 적립률 설정 |
| --- | ---: | ---: |
| Bronze | 0원 | 1% |
| Silver | 300,000원 | 1.5% |
| Gold | 700,000원 | 2% |
| VIP | 1,500,000원 | 3% |

위 값은 `1782500000000-AddMembershipTierSystem.ts`의 **기본값**이다. 운영자가 수정한 현재 운영 DB 값과 같다고 가정하지 않는다.
구매 확정된 주문의 `totalAmount`를 누적하고 기존 월간 스케줄로 등급을 평가한다. `totalAmount`는 쿠폰·포인트 차감과 배송비가 이미 반영된 결제 총액이므로 다시 할인이나 배송비를 빼지 않는다.
`pointRate`는 저장된 설정값이며, 현재 코드에 등급별 구매 포인트 자동 적립 경로는 없다. 이번 수정으로 새 적립 정책을 활성화하지 않는다.

## 보존한 정책과 한계

- 회원당 같은 쿠폰 템플릿은 한 번만 발급한다. `UQ_user_coupon`을 유지하며 생일마다 같은 템플릿을 재발급하는 정책을 만들지 않는다.
- 쿠폰 한 장을 먼저 적용하고 남은 상품 금액에 포인트를 적용한다. 배송비는 기존 서버 정책을 따른다.
- 발급된 쿠폰은 할인 조건·기간·활성 상태 변경과 삭제가 제한된다. 코드·이름·발급 한도 변경은 기존 제한 안에서 지원한다.
- minTier를 선택하지 않으면 모든 등급 상승이 대상이다. 같은 최소 금액의 등급은 조건상 동등하다.
- 만료·수량 소진·비활성·이미 발급됨은 자동 발급의 정상 제외 사유다. 실제 DB 장애는 숨기지 않고 기존 재시도 경로에 전달한다.
- 회원가입 쿠폰은 기존 메모리 이벤트 경로다. 가입과 쿠폰 발급을 묶는 내구성 큐는 없으므로 프로세스 중단까지 보장하는 재처리 시스템은 별도 작업이다.
- 과거 운영 누적액을 이번 배포에서 일괄 재계산하거나 소급 지급하지 않는다. 운영 값의 보정은 별도 비교·검토 후 수행해야 한다.
